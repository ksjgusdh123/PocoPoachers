# 게임 개요 (기획서)

원본 피치 문서("프로젝트 오메가")를 현재 구현·기존 설계 문서와 대조해 재정리한 버전. 원본은 저장소 어디에도 없었음 — 이 문서가 최초 반영.

**용어 통일:** 원본은 "벙커"/"기체"라는 표현을 쓰지만, 코드의 실제 명칭(`SC_RocketShelter` = **쉘터**, 사람 캐릭터 + 헬멧·갑옷·가방 장착)에 맞춰 이 문서부터 **쉘터**, 배터리는 **개인 생명유지 슈트 배터리**로 통일한다. 세계관 대사·연출에서 "벙커"라 부르는 건 자유 — 시스템 명칭과 별개.

구현 현황 교차 확인: [README.md#구현-현황](../README.md#구현-현황)

---

## 1. 컨셉

- **가제:** 프로젝트 오메가 (Project Omega)
- **장르:** 익스트랙션 슈터 + 탑다운 서바이벌
- **플랫폼:** PC / 협동 최대 3인 (호스트 1 + 게스트 2 — [multiplayer.md](multiplayer.md))
- **타겟:** 시간 압박형 자원 채굴 + 팀 전투를 즐기는 유저 (리썰 컴퍼니·헬다이버즈 팬층)

> 행성이 무너지기 전까지 남은 시간은 단 10분. 탐욕과 생존 사이에서 최선의 선택을 내리고, 자원을 가지고 무사히 쉘터로 복귀하라.

---

## 2. 핵심 루프

```
[1. 쉘터 준비] → [2. 행성 강하] → [3. 채굴 및 생존] → [4. 탈출 복귀] → [5. 정제 및 확장]
```

| 단계 | 내용 | 현재 구현 |
|------|------|-----------|
| 1. 쉘터 준비 | 장비 정비, 배터리 충전 | ⚠️ 수리대·강화대는 있음([shelter-raid.md](shelter-raid.md)) — **배터리 충전 수단은 미확인, 결정 필요**(§5) |
| 2. 행성 강하 | 10분 타임어택, 탐사지 진입 | ❌ 세션 타이머 미구현 — `planet.csv`의 `use_time_limit`/`max_session_time`은 죽은 컬럼([planet-sectors.md](planet-sectors.md#실제-구현-상태-코드-확인)) |
| 3. 채굴 및 생존 | 광물/보스 코어 파밍, 전투 | ✅ 채굴(`BaseOre`)·전투 있음 / 보스·코어 드롭은 신규(§4) |
| 4. 탈출 복귀 | 착지 포드 재탑승(입구=출구, 섹터당 1개), 실패 시 패널티 | ⚠️ 성공/전멸 처리 자체는 `ScenePortal`/`CheckRaidWipe()`로 있음([shelter-raid.md](shelter-raid.md#레이드-종료))이지만 "스폰과 동일한 단일 포드" 개념은 없음 — 배치 규칙은 [map-composition.md](map-composition.md#1-핵심-전제--단일-착지-포드) 참고 |
| 5. 정제 및 확장 | 쉘터 시설 업글, 개인 영구 강화 | ✅ `ShelterManager`, `PlayerEnhancement`([progression.md](progression.md)) |

## 3. 핵심 시스템

### ① 배터리 기반 타임어택 — 수치 재조정 확정

현재 `PlayerStat`은 최대 100, 조건 없이 초당 1 소모 → **약 100초**면 사망한다([player-combat.md#vital-수치](player-combat.md#vital-수치-playerstat-corecommonstatbasecs)). "10분"이라는 비전과 자릿수가 안 맞아 재조정하기로 함.

**방향:** 기존 `Battery` 스탯 자체를 10분(600) 스케일로 재조정 — 별도 타이머 시스템을 새로 만들지 않는다.

| 항목 | 현재 | 제안 (초안) |
|------|------|-------------|
| MaxBattery | 100 | 600 |
| 기본 소모 | 1/sec | 1/sec (그대로 — 이 값이 곧 "10분"의 근거) |
| 서치라이트 사용 | — | 소모 배율 ×1.5 등으로 가속 (신규) |
| 오버클럭 소모품 | — | 일정 시간 소모 배율 ×2~3 대신 파밍 속도·화력 버프 (신규) |
| `PlayerEnhancement` 레벨당 보너스 | +10 (10레벨 시 +100, 최대치의 100%) | 600 스케일에서는 비중이 16%로 줄어듦 — 강화 보너스도 같이 올릴지 결정 필요 |

**미해결:** 배터리 충전 수단이 어디에도 없음 — 레이드 중 소모품으로만 회복? 쉘터 복귀 시 자동 완충? 후자라면 "쉘터에서도 조건 없이 계속 깎인다"는 현재 로직(레이드 밖에서도 적용)부터 손봐야 함.

### ② 호전성 스케일링 환경 — 설계 보류

체류시간에 따라 시야가 줄고 스폰이 폭증하는 축과, `planet-sectors.md`의 **섹터별 고정 안개/시야/위험도** 축이 어떤 관계인지는 이번에 **결정하지 않음**. 아래 두 방향만 기록해두고 추후 논의.

| 방향 | 내용 |
|------|------|
| A. 병행 | 섹터가 진입 난이도(어느 행성을 고를지)를 정하고, 같은 섹터 안에서는 체류시간이 위험도를 추가로 올림. 두 축 독립 |
| B. 대체 | 섹터별 고정 스펙을 폐기하고, 모든 행성이 같은 기준선에서 시작해 체류시간만으로 난이도가 오름 |

구현 여부와 무관하게 **이 결정 전까지는 `planet-sectors.md`의 고정 스펙 표를 그대로 유지**한다(변경하지 않음).

### ③ 협동형 쉘터 경제

현재 흐름 그대로 유지 — 채굴한 자원은 즉시 귀속되는 게 아니라, 쉘터로 복귀해 `Storage`(공유 창고, uid=1)에 드래그로 넣어야 팀 자산이 된다([shelter-raid.md#쉘터-sc_rocketshelter](shelter-raid.md#쉘터-sc_rocketshelter)). 자동 귀속으로 바꾸는 안은 이번엔 다루지 않음.

## 4. 엔딩 — 보스 코어 경제 확정

**목표:** 쉘터 중앙의 [유한자원생성기] 4단계 부품을 조립하고 중앙 콘솔에서 "지구 복귀" 버튼을 활성화.

**최종 요구 자원:**
- 보스 코어 3개 (적립형)
- 오메가 광물 50개 (섹터 04 전용 채광, [planet-sectors.md](planet-sectors.md) 기준 티어4 집중 자원)

**보스 코어 경제 (이번에 확정):**

기존 `planet-sectors.md`는 "섹터04 진입 = 보스 코어 1개 **소비**"라 되어 있는데, 이게 엔딩용 3개 적립과 충돌할 수 있어 아래로 해결:

> **보스 처치 시 코어 2개 드롭 — 1개는 즉시 다음 섹터04 진입에 쓸 수 있고, 1개는 엔딩 제단에 적립된다.**

- 보스는 **섹터 02·03·04** 각각 고유 개체로 배치 제안 (섹터 01은 학습 구간으로 보스 없음 — 기존 위험도 캡 설계와 일관, [planet-sectors.md](planet-sectors.md) 참고).
- 섹터04 보스도 코어 2개를 드롭하므로, 한 번 진입해서 보스를 잡으면 다음 진입 자금이 자체 순환된다(적립분 1개는 그대로 쌓임).
- 즉 엔딩까지 최소 경로: 섹터 02 또는 03 보스 1회 처치(코어 획득 1개 적립 + 1개로 섹터04 진입) → 섹터04에서 보스 처치(코어 1개 추가 적립 + 1개로 재진입 자금) → 이후 오메가 광물 50개를 채울 때까지 섹터04 반복.

**미구현:** 보스 전투/드롭 로직, 유한자원생성기, 엔딩 콘솔 전부 신규이며 [todo.md](todo.md#p2--신규-시스템)에서 추적한다.
