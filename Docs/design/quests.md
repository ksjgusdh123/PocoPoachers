# 퀘스트 진행 방식

범위: 개인·공유 퀘스트의 지정과 호스트 권위 진행. 개인 진행의 디스크 저장·복원은 미구현이다.

`PocoPoachers/DataTable/quest.csv`의 `progress_mode`를 지정하고 **Tools → Generator → Tables**를 실행한다. 기존 퀘스트는 `Shared`로 유지한다. CSV는 UTF-8 BOM으로 저장한다.

| 값 | 동작 |
|---|---|
| `Shared` | 수락·제출량·완료 상태를 파티에 전파. 기존처럼 완료 버튼을 누른 사람에게 보상 지급 |
| `Personal` | 호스트가 플레이어 ID별 수락·제출량·완료를 관리하고 해당 플레이어에게만 상태와 보상 승인 전송 |

목록과 상세 제목에 `[개인]` 또는 `[공유]`를 표시한다. 제출 아이템은 두 방식 모두 제출자의 인벤토리에서 차감한다.

개인·공유 모두 클라이언트는 요청만 보내고 호스트가 수락 조건·제출 목표와 잔여 수량·완료 조건을 검증한다. 개인 진행은 `(소유자 ID, 퀘스트 ID)`, 공유 진행은 소유자 0으로 관리한다. 게스트 소유자는 실제 UDP 송신자 ID로 결정한다.

진행도는 호스트 메모리에 보관하며, 접속 시 공유 상태와 접속자의 개인 상태를 전송한다. 호스트 세션이 유지되는 동안 같은 플레이어 ID로 재접속하면 메모리 상태를 다시 받는다. 개인 진행은 기존 공유 저장 데이터에 포함하지 않으며 호스트 세션 종료 후에는 복원하지 않는다.

상태는 제출량 절대값과 변경 번호로 전송해 중복·역순 수신을 처리한다. 제출 요청 번호로 중복 반영을 막고, 로컬에서 미리 차감한 수량 중 승인되지 않은 수량은 요청자에게 반환한다. 인벤토리 보유 검증은 기존처럼 클라이언트의 차감 보고에 의존한다. 완료는 호스트에서 한 번만 승인하며 기존 정책대로 승인된 완료 요청자만 보상을 받는다. 보상/환불은 인벤토리가 없거나 가득 차면 현재 세션의 지급 대기열에 남긴다.

## 선행 퀘스트

`quest.csv`의 `prerequisite_quest_ids`에 `9001;9002`처럼 지정한다. 나열된 퀘스트를 **모두 완료**해야 수락할 수 있으며, 빈 칸은 조건 없음이다. 기존 행은 조건 없이 유지한다.

선행 조건은 수락을 요청한 플레이어 기준으로 검사한다. 개인 선행 퀘스트는 요청자 본인의 완료 여부, 공유 선행 퀘스트는 파티 완료 여부를 사용한다. 공유 퀘스트에 개인 선행 조건을 지정하면 조건을 채운 플레이어 한 명이 수락한 순간 파티 전체가 진행한다.

잠긴 퀘스트는 목록에 `[잠김]`을 표시하고 상세에 선행 완료 상태를 보여준다. 수락 불가인 NPC 선택지는 숨기며 클릭 시와 호스트 수신 시에도 조건을 확인한다. 생성기는 없는 ID·중복·자기 참조·순환 의존성을 오류로 처리한다.

## NPC 대화에서 퀘스트 받기

NPC에게 말을 걸면 `dialogue.csv`의 기본 대사 체인이 먼저 흐르고, 체인이 끝나면 그 NPC의 퀘스트 목록이 뜬다. 목록은 `quest.csv`의 `npc_id`로 자동으로 묶이므로 퀘스트를 늘려도 `dialogue_choice.csv`를 손대지 않는다. 퀘스트마다 대사 세 개를 `quest.csv`에 지정한다.

| 컬럼 | 언제 나오는가 | 자동으로 붙는 선택지 |
|---|---|---|
| `offer_dialogue_id` | 아직 수락하지 않음 | `[수락한다]` `[거절한다]` |
| `progress_dialogue_id` | 수락함, 목표 미달 | `[돌아가기]` |
| `complete_dialogue_id` | 수락함, 목표 달성 | 마지막 대사를 넘기면 호스트에 완료 요청 |

목록에는 퀘스트 이름만 띄운다 - 상태는 고르고 들어갔을 때 나오는 대사로 구분한다. **완료한 퀘스트와 선행 조건이 안 찬 퀘스트는 목록에서 숨긴다.** 마지막 항목은 대화를 닫는 `돌아가기`다.

대사 id가 `0`이거나 `dialogue.csv`에 없으면 `quest.csv`의 `description`을 대신 띄운다. 생성기는 없는 대사 id와 퀘스트·대사 간 `npc_id` 불일치를 오류로 처리한다.

`dialogue_choice.csv`에 손으로 쓴 선택지가 있으면 그 줄에서는 목록 대신 그 선택지가 나온다 - 기존 분기 방식도 그대로 쓸 수 있다. 퀘스트와 무관한 안내용 NPC는 `NpcDialogueInteractable`의 `Skip Quest Menu`를 켜면 목록 없이 대화만 끝난다.

선택지 버튼은 `DialogueUI` 프리팹에 꽂아둔 슬롯보다 많아지면 0번 슬롯을 복제해 런타임에 늘린다. 배치는 부모 `SelectTexts`의 `VerticalLayoutGroup`과 `ContentSizeFitter`가 맡는다 - 피벗이 우하단이라 목록이 길어지면 맨 아래 칸은 그대로 있고 위로 쌓인다. 숫자키는 1~9까지만 받는다.


## 제출 후 NPC에게 보고

퀘스트 창의 버튼은 항상 `제출하기`이며 모든 목표 아이템을 제출하면 비활성화된다. 제출만으로는 퀘스트가 완료되거나 보상이 지급되지 않는다. NPC에게 다시 말을 걸어 해당 퀘스트 번호를 선택하고 완료 대사의 마지막 줄을 넘겨야 호스트가 완료 조건을 검사하고 보상을 승인한다. 별도의 `완료하기` 선택지는 표시하지 않는다. 완료 대사 ID가 0이면 퀘스트 설명을 확인하고 넘긴 뒤 같은 방식으로 처리한다.
